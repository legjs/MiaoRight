# 保险箱功能 · 执行记录(2026-11-19)

本文记录保险箱的早期实现。当前管理入口为主窗口独立的「保险箱」页，操作见[中文版 README](../README.zh-CN.md#加密保险箱)。

用户确认的四项决策:存储方案选 hdiutil AES-256 加密磁盘镜像;密码默认每次会话手动解锁、可选存钥匙串;「加入保险箱」为移动并确认;管理入口为右键菜单页内嵌管理区。

## 关键实测结论(驱动实现)

- `hdiutil create … -stdinpass` 读取原始字节到 EOF:**不带换行**写入;带换行的密码会认证失败(创建时换行会成为密码的一部分)。
- 干净未挂载状态下错密码返回「认证错误」、退出码 1;已挂载时 `attach` 直接返回现有挂载点、不校验密码——引擎先查挂载状态,异常退出后按已解锁处理。
- 创建镜像不会把密码写进登录钥匙串;`-mountpoint` 可指定确定性挂载点(引擎固定为 App Group 容器旁的 `VaultMount`)。
- 挂载后 `mdutil -s` 显示 Indexing disabled,且引擎在卷根补写 `.metadata_never_index` 双保险。
- 中文文件名/目录、卸载后 bands 无明文名泄露、按挂载点 detach 均实测通过。

## 实现

- `MiaoRightShared/VaultConfig`:App Group 只存 `vault.configured` 与镜像路径(密码永不落盘),扩展据此判断「加入保险箱」菜单可用性。
- `MiaoRightKit/VaultStore`:创建/解锁/锁定/销毁、内容列表、移入(`FileOperationJournal.perform` 支持撤销)、取出(复制语义)、删除;自动锁定覆盖空闲(CGEventSource 键鼠空闲,默认 15 分钟)、睡眠、退出(同步尽力卸载);「记住密码」走登录钥匙串,离屏测试不触达钥匙串。
- 右键「加入保险箱」(按需添加,进「更多操作」组):`ScriptExecutor` 路由到 `VaultTaskPresentation`,内嵌表单未创建先建、锁定先解锁、解锁后确认移入;`shouldConfirm` 对该入口返回 false,确认在表单内完成。
- 管理行 `VaultPreferencesView` 接入右键菜单页(默认折叠,复用 PreferenceDisclosureStyle);处理期间禁用切页与重复执行。
- 双语:`ActionNames` 补「加入保险箱 / Add to Vault」与描述映射;`ActionEmoji` 为 🔐。

## 已知边界与未尽事项

- hdiutil 命令序列按上述实测逐条编写,但**引擎级创建→解锁→移入→取出→锁定的端到端闭环未在隔离环境实跑**(隔离约束禁止测试进程执行 hdiutil);首次真实使用时建议先建一个测试密码的空保险箱验证。
- Finder 前台点击「加入保险箱」、真实多显示器与 VoiceOver 未实机验证,延续本轮不影响用户使用的约束。
- APFS 上原文件明文删除无法保证防恢复;忘记密码不可恢复,创建表单已注明。
- 修改保险箱密码需重建镜像迁移,本轮未提供。
