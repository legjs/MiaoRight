# 妙右：轻量工具重设计

## 用户已经明确的事实

实际高频使用五类能力：复制文件路径、用指定应用快速打开、快速打开终端、剪切粘贴、剪贴板记录。其余能力没有形成当前用户的使用习惯，自定义流程甚至尚未测试。未来希望供其他用户使用，因此需要容纳不同需求，但不能将全部能力和内部概念同时交给每个人。

上一版建议把产品推向图片转换、文件整理与流程编排，偏离了这些已知事实。“能力很多但不顺手，界面也不够好看”才是这次重设计的核心问题。

## 产品定义

**妙右是随手使用的 Mac 效率工具：在 Finder 里快速复制、移动和打开，在需要时找回剪贴板内容。**

体验由两个日常入口和一个低频管理窗口构成。日常入口是 Finder 右键与剪贴板快捷键；主窗口负责偏好设置和按需添加功能。产品不要求用户进入工作台、发现中心或运行中心才能完成常用操作。

五类高频工具是本轮设计的核心样本，不等于已经证明所有用户都应默认启用同样的一组功能。对外版本的默认集合应通过真实任务验证，其他用户通过简单的添加方式得到适合自己的菜单。

## 功能组织

| 能力 | 普通用户看到什么 | 只需设置什么 |
|---|---|---|
| 复制路径 | 复制文件路径 | 默认即可使用；高级选项以后按需展开 |
| 应用打开 | 用应用打开 → 已选择的常用应用 | 从本机选 App，或将 App 拖入 |
| 终端 | 在终端打开 | 选择已安装的终端，或设为不显示 |
| 剪切粘贴 | 剪切、粘贴到此处 | 显示待移动状态，目的地操作成功后清除状态 |
| 剪贴板 | 快捷键呼出的历史列表 | 记录开关、快捷键、是否自动粘贴、保留时间 |
| 其他能力 | 添加功能 | 默认按用途列举支持的功能，可筛选或搜索后添加 |

应用列表必须来自本机可用 App；不能让用户先看到十几个未安装的编辑器。终端选择同样只列可用目标，并说明未安装或失效的路径。示意图中的应用只是样本。

“剪切与粘贴”按文件事务处理，不能与剪贴板历史共用模糊的选中状态。待移动提示包含文件数量；取消、源文件不存在、同名冲突和跨卷移动要有明确结果。

添加功能不引入插件市场、模板商城或复杂能力包。按用途分段列举任务名称、简短说明和添加按钮，搜索与分类用于缩小范围；已添加条目显示勾选状态。移除功能可直接在管理列表完成。现有用户配置迁移时保留，并提供恢复入口。

## 主窗口

采用接近 macOS 原生偏好设置的中小型窗口，不再强制最小宽度 1120。窗口宽高以真实内容排版验证后确定，当前默认 780 × 600，最小 680 × 540 点。

64 点顶部栏居中显示三个胶囊入口，无侧栏：

1. **右键菜单**：列表管理常用工具、常用应用和终端；底部提供添加功能与按需菜单预览。
2. **剪贴板**：清楚分离记录历史和显示面板，提供自动粘贴行为与保留策略。
3. **通用**：登录启动、语言、外观三选、生效范围、权限与诊断；底部显示程序图标、名称与版本。

主窗口默认显示右键菜单，不再展示“已启用 23/105”之类的功能完成度。完整菜单预览按需打开，不永久占据右侧。扩展健康时只给轻量状态；需要用户修复时，直接出现对应说明与操作。

首轮不提供面向普通用户的空白流程编辑器、原子选择器、产物类型槽、顶层分类或大型运行中心。高级编辑若以后仍有真实需求，可以另作高级入口；不能成为普通工具的必经路径。

## 视觉方向

选择克制的原生工具风格，主要识别来自秩序、排版与动作反馈。

- 系统字体，正文清楚可读，标题仅建立层级，不使用品牌渐变字。
- 主窗口和剪贴板采用原生轻微毛玻璃，可选跟随系统、浅色或深色，并保存选择。
- 一种系统蓝强调色，用于开关、当前选中项和主要按钮。
- 单色 SF Symbols 表达工具类型，实际 App 使用自身图标。移除每个动作上的彩色图标底板、彩色描边与 emoji 混搭。
- 以紧凑列表和必要分隔线组织内容，不再把所有功能切成同等大小的磁贴。
- 原生窗口材质保留轻微背景透出，文字清晰优先；减少透明度或增加对比度时回退实色，不额外叠加装饰光晕。
- 成功反馈轻而明确：路径已复制、已用某 App 打开、已移动多少项。失败要说明可采取的下一步。

## 右键菜单

固定顺序，文字直接说出操作。常用应用通常收在“用应用打开”子菜单中；是否将少数应用直接放一级，作为后续可选偏好验证。菜单不自动按使用频率不断换位置。

在不适用的上下文中隐藏或明确禁用操作，例如没有待移动文件时禁用粘贴；文件场景打开终端时明确使用所在文件夹。复制路径默认输出常用的原始路径格式，带引号等额外格式按实际需求引入。

与 Finder 保持同样的菜单语法、尺寸和图标密度。菜单预览和真实 Finder 菜单必须共享构建规则。此前发现的顶层动作遗漏、常用关闭后消失仍应修复，避免迁移时丢失已有功能。

## 剪贴板

保留刚完成的搜索/输入法保护、多选、固定与自动收起、多屏裁剪。改为更易扫读的记录列表，正文摘要在前，来源和时间为次要信息。

面板宽度需要支持常见文本路径，初稿在约 300–340 点范围验证，长内容允许查看详情。无需给每条记录都加粗重边框或大图标。搜索框稳定置顶，键盘选中与勾选多项使用不同视觉状态。

设置中真正提供暂停采集，而不只是隐藏窗口。选择条目后的复制与粘贴反馈分开；未获辅助功能授权时清楚显示已复制及授权入口。多选含不支持合并的类型时不能静默忽略。

## 实施切分

第一步，用这份主窗口、右键菜单和剪贴板原型确认方向；不先重写整个执行引擎。

第二步，重建原生界面壳和常用应用/终端管理，迁移已有设置，统一真实菜单与预览。

第三步，完成复制路径、打开应用、终端、剪切粘贴及剪贴板的端到端检查，覆盖授权失败、目标丢失、输入法、多屏和键盘操作。

第四步，接入按需添加的其他能力。尚未验证的自定义流程不作为对外版本的主打能力；公开入口须以测试结果为依据。

验收以实际任务为准：能否在 Finder 一眼找到常用项；选 App 是否无需输入路径；终端是否打开正确目录；文件移动是否清楚；剪贴板能否快速搜到并复制；遇到问题能否理解提示。界面还应检查英文长度、键盘焦点、VoiceOver 和浅深色。

## 交付前需要另行解决的约束

当前仓库 AGENTS 与 README 明示基于上游许可证，仅供个人本地使用、不得分发。用户希望提供给他人使用，与当前仓库注明的边界存在冲突。后续对外交付前需要单独核实并解决授权或独立实现边界；本轮界面重设计不解决这项约束。

## 顶部导航与材质最终调整（2026-11-18）

用户后续确认顶部胶囊切换，移除原 156 点侧栏及顶部品牌文字。顶部栏高 64 点、三页导航居中，右侧显示连接状态。通用页底部显示 36 点程序图标、妙右名称和版本。外观保留跟随系统 / 浅色 / 深色三选，保存 appAppearance；不再将“始终跟随系统”作为约束。

主窗口和剪贴板面板使用 FrostedWindowBackground。此前参数为 NSVisualEffectView.sidebar / behindWindow / active、alphaValue 0.99，并根据当前主题显式选择 vibrantLight / vibrantDark；浅色叠加白色 0.20、深色叠加黑色 0.40。透明度依据用户“太透明”的反馈收敛，保持轻微透出。减少透明度或增加对比度仍回退系统实色。顶部选中胶囊使用 response 0.25、dampingFraction 1 的 spring，Reduce Motion 时取消动画。

最终图标为蓝底白色菜单+光标的原创矢量方案，源文件 Packaging/Icons/GenerateIcons.swift。scripts/generate-icons.sh 自动导出 AppIcon / FinderIcon 的 PNG、各十项 iconset 与 ICNS（16–1024 像素），以及 18/36 像素透明黑色菜单栏模板。build-app.sh 每次导出并复制到相应 bundle，plist 声明图标文件；不是每次构建调用图像生成模型。24 张 PNG 均含来源记录，扫描无缺失。

此前 release 构建和 codesign --verify --deep --strict 通过。同源原生 fixture 已断言 system=nil、light=Aqua、dark=DarkAqua，以及各视图树存在 sidebar / active / alpha 0.90 的 NSVisualEffectView；两个 ICNS 可由 NSImage 解码。最终四张 fixture 截图位于 .impeccable/review/glass，覆盖中文浅色、英文深色最小宽度、剪贴板设置和通用页底部信息；fixture 无 appex 所产生的未启用提示不代表实机扩展异常。

实机已确认三种外观切换、最终深色材质与 Finder 扩展连接，测试后已恢复用户原来的跟随系统。通用页底部由 880 点高原生 fixture 核对；滚动自动化遇到 noWindowsAvailable，不能声明实机滚动全链路通过。VoiceOver、物理三屏、权限及减少透明度/增加对比度的实机全链路仍未全面验收。既有 16 项独立回归记录不等同于此次所有外观场景的 XCTest 验收。

用户随后将不透明度从 90% 调整为 96%（材质层透明度 4%）；浅深色遮罩及系统辅助功能回退保持原有行为。此前 alpha 0.90 的截图与 fixture 记录保留为历史验证范围。

随后依据用户反馈，将材质层不透明度进一步调整为 99%（透明度 1%），保留现有浅深色遮罩。


## 磨砂材质接线修正

用户指出 99% 图层不透明度虽能减少透出，却看起来像纯浅色。此前把 NSVisualEffectView 的 alpha 当成实际背景透明度解释并不准确。现将主窗材质直接作为 NSHostingView 下方的原生兄弟视图，防止 SwiftUI 背景合成遮盖或压平材质；不覆盖内容绘制或拦截控件点击。材质改用窗口后景专用 underWindowBackground / behindWindow / active，模糊层 alpha 保持 1；浅色白色 0.60、深色黑色 0.50 底色由原生子视图独立绘制。剪贴板保留原滑动裁剪机制，在容器内使用同一材质。旧 alpha 0.90 / 0.96 / 0.99 的百分比和截图仅为历史记录，不代表当前实现的实际背景透出比例。
